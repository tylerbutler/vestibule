# Secret lifecycle

Vestibule is for demos and prototypes. It has not had a security audit and is
not production-ready. This inventory describes the current source-level
handling of OAuth secrets. It does not claim forensic memory erasure, protection
from VM dumps, or protection after an explicit accessor returns a raw value.

## Runtime representation

Client secrets, client assertions, access tokens, and refresh tokens use
`vestibule/internal/secret`. The wrapper captures the string in a closure.
Normal Gleam inspection and Erlang `~p` formatting show the function but not its
captured environment. Raw values remain in BEAM process memory and are exposed
when code calls an accessor to construct a request.

## Client authentication migration

`ClientAuth` is now opaque. Replace `config.PublicClient` with
`config.public_client()`, `config.ClientSecret(value)` with
`config.client_secret_auth(value)`, and `config.ClientAssertion(value)` with
`config.client_assertion_auth(value)`. Use `config.client_auth_kind` instead
of matching on the old constructors. The explicit `config.client_secret` and
`config.client_assertion` accessors take a `ClientConfig` and return the raw
credential for request construction.

## Source-to-sink inventory

| Secret class | Source and storage | Intended sink | Retention and cleanup | Disclosure notes |
| --- | --- | --- | --- | --- |
| Client secret or assertion | Application configuration; closure-wrapped in `ClientAuth`, then stored in `ClientConfig` and `Registry` | Token endpoint request body or client-auth header | Lives as long as the application configuration and any copied terms | `ClientAuth`, `ClientConfig`, and `Registry` redact under normal Gleam and Erlang term formatting. `config.client_secret` and `config.client_assertion` expose the raw value only for request construction. |
| Authorization code | Provider callback query parameter; passed through the callback flow | Token endpoint request body | Callback-local and intended for one exchange | Stored as a plain string while in flight. It is not added to structured logs. Provider request terms can contain it after request construction. |
| PKCE verifier | Generated for an authorization request; closure-wrapped in `AuthorizationRequest`, then stored as a plain string in `state_store` | Token endpoint request body | Default state-store TTL is 10 minutes; deleted on consume, mismatch, expiry, or sweep | `AuthorizationRequest` redacts under normal term formatting. ETS values remain printable. Structured logging rejects the `code_verifier` field name. |
| State and OIDC nonce | Random values generated by core; closure-wrapped in `AuthorizationRequest`; stored as plain strings in `state_store` | State comparison and ID-token nonce comparison | Same single-use and 10-minute default state-store lifecycle as the verifier | The authorization request term redacts them. State and nonce are intentionally present in the browser authorization URL after the URL accessor is called. Do not log callback parameters or stored ETS values. |
| Access and refresh tokens | Decoded from token responses; closure-wrapped in `credential.Credentials` | Authorization header and refresh request body | Retained as long as application-held credentials; Vestibule has no persistent token store | `Credentials` and `Auth` redact under normal term formatting. `credential.token` and `credential.refresh_token` return raw strings. Request terms contain raw headers or bodies after construction. |
| ID token | Provider token response; closure-wrapped with the exchange artifact dictionary | Nonce and provider-claim validation | Callback-local unless application or provider code retains the exchange term | `ExchangeResult` redacts under normal term formatting. `strategy.exchange_artifacts` explicitly returns the raw artifact dictionary. The ID token is not copied into `Credentials`. |
| Signed session identifier | Random state-store key, signed into the middleware cookie | Cookie verification and state-store lookup | Cookie is cleared by middleware after callback; state entry is consumed or expires | The identifier is not a provider token, but possession binds the browser to an in-flight flow. Structured logging rejects session and cookie field names. |
| Cookie-signing key | Application input to Wisp or Mist middleware | Cookie signature generation and verification | Application lifetime; Vestibule does not persist or rotate it | Passed as a plain string. Do not render middleware configuration or signing inputs. Rotation is application-owned and invalidates outstanding login cookies. |
| Apple signing material | Application-owned Apple private key creates a signed client-secret JWT outside Vestibule | Apple token endpoint | Private-key retention is entirely application-owned; JWT follows the client-secret lifecycle above | Vestibule receives the signed JWT, not the private key. Use `config.client_secret_auth(jwt)`. |

## Errors, logs, and request placement

- Structured core logs use event names, phases, outcomes, counts, status codes,
  and error categories. The logger drops known sensitive field names, including
  tokens, client assertions, authorization codes, verifiers, state, nonces,
  session IDs, cookies, and response bodies. Snake-case, kebab-case, camel-case,
  and case variants are normalized before filtering.
- Core validation errors use fixed messages and do not interpolate callback
  codes, state, nonces, verifiers, or tokens.
- Bearer access tokens are placed in the `Authorization` header. Reviewed
  request builders do not place access or refresh tokens in URL query strings.
  Token exchanges place codes, verifiers, client credentials, and refresh
  tokens in request bodies.
- Provider-response errors do not copy response bodies, descriptions, URIs, or
  unknown error codes into public errors. This prevents a provider from echoing
  submitted secrets through those fields
  ([#174](https://github.com/tylerbutler/vestibule/issues/174)).
- Closure wrapping protects ordinary term rendering only. A crash after an
  accessor has produced a raw string, or while an HTTP request term contains a
  raw header or body, can still disclose that value.

Remaining follow-up defects track raw state-store callback artifacts
([#175](https://github.com/tylerbutler/vestibule/issues/175)) and plain
middleware signing keys
([#177](https://github.com/tylerbutler/vestibule/issues/177)). Exchange-result
redaction and structured-log alias filtering address
[#176](https://github.com/tylerbutler/vestibule/issues/176) and
[#178](https://github.com/tylerbutler/vestibule/issues/178), respectively.

## Application expectations

Consume authorization state once, retain the default 10-minute TTL or a shorter
one, and sweep expired entries. Clear signed session cookies after callback.
Keep access and refresh tokens only as long as the application needs them and
use an encrypted application-owned store if they must survive process restart.
Rotate client credentials and cookie-signing keys according to provider and
application policy. Never log full configuration, authorization requests,
callback parameters, exchange results, credentials after accessors run, or HTTP
request/response bodies.
