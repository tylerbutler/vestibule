## v0.0.1 - 2026-08-31

### Changed

- Repositioned as demo-ready auth: not security audited, not for production use

### Fixed

- Module documentation now uses `////` doc comments so it appears in generated documentation instead of silently attaching to the first import

### Dependencies

- Switch test framework from startest to gleeunit
- Updated vestibule to 0.1.0

### Security

- Confirm the profile URL (`me`) returned by the token endpoint against the authorization server the flow used (IndieAuth §5.3.4) before using it as the user's identity, and require the userinfo endpoint's `me` to match. Previously the userinfo response's `me` was trusted verbatim and the token response's `me` was ignored, letting a malicious or shared authorization server assert any user's identity
- Discovered IndieAuth endpoints (metadata URL, authorization, token, issuer, userinfo) and endpoints restored via `parse_endpoints` must now be public HTTPS URLs, and profile URLs must not point at localhost or other non-public hosts. Previously an attacker-controlled profile page could direct the server's token and userinfo requests at loopback, private, or cloud-metadata addresses (SSRF)
- Require HTTPS identities and route dynamic endpoints through DNS-pinned, bounded secure requests
