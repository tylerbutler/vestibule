## v0.1.0 - 2026-08-03

### Breaking

- Generate and validate the OIDC `nonce`. OIDC strategies now emit a `nonce` on the authorization request and constant-time validate it against the `id_token`'s `nonce` claim on callback, rejecting mismatched or missing-but-expected values with `error.invalid_nonce()`, an AuthError of kind `InvalidNonceKind`. Adds the `vestibule/nonce` module, `strategy.with_nonce`, the `authorization_request.nonce` accessor on opaque `AuthorizationRequest`, and an `expected_nonce` parameter on `handle_callback`; `state_store` now persists the nonce, so `store`/`try_store` take a `nonce` argument and `consume`/`peek` return `#(state, code_verifier, Option(nonce))`.
- OIDC discovery moved out of the core package. Add the vestibule_oidc package and import vestibule_oidc instead of vestibule/oidc.
- `Auth` and `UserInfo` are now opaque. Construct `Auth` with `auth.new` and read fields with the `auth.uid`/`provider`/`info`/`credentials`/`extra` accessors. Build `UserInfo` with `user_info.new` plus the `with_*` helpers and read fields with the `user_info.name`/`email`/`nickname`/`image`/`description`/`urls` accessors. Direct construction and field/pattern-match access no longer compile.
- `strategy.new` is now a two-argument builder: `strategy.new(provider:, default_scopes:)` followed by `with_authorize_url`, `with_exchange_code`, `with_fetch_user`, the optional `with_refresh`, and the optional `with_nonce` (replacing the old `uses_nonce` argument). Provider capabilities are now extensible without future breaking constructor changes. Strategies built without `with_refresh` return `error.refresh_unsupported()`, an AuthError of kind `RefreshUnsupportedKind`, from `vestibule.refresh_token`; a missing required capability (authorize URL, code exchange, or user fetch) fails with `error.config(reason:)`, an AuthError of kind `ConfigKind`. Custom strategies must migrate from the old 7-argument `strategy.new` to the builder API.
- `AuthError(e)` is now an opaque type. The public variant constructors have been replaced by constructor functions (`error.state_mismatch`, `error.invalid_nonce`, `error.missing_callback_param`, `error.code_exchange`, `error.user_info`, `error.provider`, `error.http`, `error.decode`, `error.network`, `error.config`, `error.refresh_unsupported`, `error.custom`) and accessor functions. Inspect errors with `error.kind` (returns an `ErrorKind` enum with an `OtherKind` catch-all so new kinds never break exhaustive matches), `error.phase`, `error.message`, `error.provider_error` (+ `provider_code`/`provider_description`/`provider_uri`), `error.http_status`, `error.http_summary`, `error.missing_param`, and `error.custom_payload`. Raw HTTP response bodies are no longer exposed; `error.http_summary` returns a sanitized, truncated summary. Code that pattern-matched on `AuthError` variants must migrate to the constructor and accessor functions.
- Split durable client configuration from per-request authorization options. Migrate `config.new(id, secret, uri)` to `config.new(client_id: id, redirect_uri: uri, auth: config.ClientSecret(secret))`; use `auth: config.PublicClient` instead of an empty secret for public clients. Move old config-level scopes and extra authorization params to per-request options with `config.authorize_options() |> config.with_scopes(...)` and `config.authorize_options() |> config.with_extra_params(...)`, then pass them with `options:` to `vestibule.create_authorization_request`.
- GitHub strategy moved out of the core package. Add the vestibule_github package and import vestibule_github instead of vestibule/strategy/github.

### Added

- `vestibule/state_store` — the ETS-backed OAuth state store (CSRF state + PKCE verifier) is now part of core `vestibule`, shared by all transports (`vestibule_wisp`, `vestibule_mist`). It includes consume-oriented reads, richer initialization/store errors, and opportunistic cleanup of expired sessions.
- Structured logging is now a supported Provider SDK module at vestibule/logger (promoted from vestibule/internal/logger) so strategy packages can emit log events without importing an internal module.

### Changed

- `ClientConfig` is now opaque. Direct field access (e.g. `config.client_id`) must be replaced with `config.client_id/1`, `config.client_auth/1`, `config.client_secret/1`, and `config.redirect_uri/1`. Per-request scopes and extra authorization parameters now live on `AuthorizeOptions` and are exposed through `config.scopes/1` and `config.extra_params/1`.
- `strategy.exchange_code` now returns an opaque, accessor-based `ExchangeResult` with `strategy.exchange_credentials` and `strategy.exchange_artifacts` accessors, and `strategy.fetch_user` receives that exchange result so provider-specific token response artifacts can flow explicitly into user resolution. Providers with no artifacts can wrap credentials with `strategy.exchange_result(credentials)`.
- Public types `Strategy`, `UserResult`, `ExchangeResult`, and `AuthorizationRequest` are now opaque. Construct via `strategy.new`, `strategy.user_result`, `strategy.exchange_result`, and `authorization_request.new`; read fields via the accessor functions on each module.
- The vestibule/transport_flow module is now marked internal. It was shared plumbing for the first-party vestibule_wisp and vestibule_mist middlewares and was never intended as a stable public API; its tuple shapes and error variants may change without a major version bump.

### Security

- State validation now rejects empty and whitespace-only state tokens, closing a potential CSRF bypass.
- State is now validated before provider error details are surfaced in `handle_callback`, preventing information leakage on CSRF attempts.
- Redirect URIs are now validated to use HTTPS. HTTP is permitted only for `localhost` and `127.0.0.1` (local development). An invalid or non-HTTPS redirect URI now returns an AuthError of kind `ConfigKind` instead of panicking.
- OIDC userinfo responses no longer return unverified email addresses. When `email_verified` is `false` or absent, the `email` field in `UserInfo` is set to `None`.
- Documented PKCE, state, JWT verification, and the OIDC nonce gap in the root README. No behavior change.
- `Credentials` access and refresh tokens are now wrapped in an internal secret type, so `string.inspect`, Erlang `~p` formatting, logs, and crash reports redact them even when an `Auth` or `Credentials` value is rendered directly. Public accessors (`credentials.token`, `credentials.refresh_token`) and `credentials.new` are unchanged.
- `registry.register` now rejects a duplicate provider registration with `Error(DuplicateProvider(name))` instead of silently replacing the existing strategy/config, preventing provider impersonation from dynamic or untrusted provider configuration. Trusted callers can use the new `registry.register_or_replace` to intentionally overwrite an entry.
- OIDC issuer and discovered endpoint URLs (`oidc.new_config`, `oidc.discovery_url`, `oidc.parse_discovery_document`) now require HTTPS and reject loopback, private, link-local, and other non-publicly-routable hosts, closing an SSRF vector where a malicious issuer could publish internal `token_endpoint`/`userinfo_endpoint` values. Redirect URIs still allow `http://localhost` for local development.
