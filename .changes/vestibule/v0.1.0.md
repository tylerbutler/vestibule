## v0.1.0 - 2026-08-31

### Breaking

- Add a `reason` field to `StateStoreError`'s `TableCreateFailed`, `InsertFailed`, and `CleanupFailed` variants so unmapped ETS owner failures carry the raw failure reason
- Rename modules and state-store APIs, add secure bounded HTTP transport, and expose sans-I/O provider helpers
- State store sessions are now bound to the provider that started the flow: `state_store.try_store`/`try_store_with_ttl` take a `provider` argument and `consume`/`peek` require the same provider or fail. `transport_flow` threads the strategy's provider through both phases, so a session minted for one provider can no longer satisfy another provider's callback (OAuth mix-up attack leading to login CSRF or account-linking takeover)

### Changed

- Repositioned as demo-ready auth: not security audited, not for production use

### Fixed

- `handle_callback` no longer falls open when a nonce-using strategy is called with `expected_nonce: None`; it now fails with `InvalidNonceKind`, so a caller that forgets to store the nonce cannot silently lose id_token replay protection
- The state store now heals itself if its unsupervised ETS owner process dies: the next operation respawns the owner and recreates the table with the same capacity instead of failing every login until the VM restarts. Callers no longer wait out the 5 s timeout when the owner is dead, and stray messages no longer accumulate in its mailbox

### Dependencies

- Switch test framework from startest to gleeunit

### Security

- `provider_support.require_public_https` now rejects numeric hosts that are not a canonical dotted quad (`127.1`, `2130706433`, octal `0177.0.0.1`) and trailing-dot names like `localhost.`, all of which the system resolver treats as loopback. Added `provider_support.require_public_host` for server-fetched URLs where plain HTTP is allowed but non-public hosts are not
- The state store no longer scans the whole table on every insert (an unauthenticated client could make every login request and callback time out by starting flows in a loop). Expired sessions are now swept by the owner process on a timer and reclaimed on demand; stores are bounded by a live-session cap (default 100 000, configurable with the new `state_store.try_init_with_capacity`) and refuse new flows with `StoreFull` when full. Added `state_store.sweep_expired`
