## v0.1.0 - 2026-08-03

### Breaking

- Update middleware APIs for the vestibule `ClientConfig` and `AuthorizeOptions` split. Register configs with `config.new(client_id: id, redirect_uri: uri, auth: config.ClientSecret(secret))` or `auth: config.PublicClient`; move old config-level scopes and extra params to `config.authorize_options() |> ...` and pass them to request-phase middleware with `authorize_options:`.

### Changed

- Stabilized the Wisp middleware for a 1.0 release with an opaque ETS-backed `StateStore`, server-side OAuth session TTLs, configurable cookie options, fail-closed malformed POST callback parsing, and compatibility with the current `vestibule` auth error and strategy contracts.
- Middleware now reads `AuthorizationRequest` fields through the new `authorization_request.url` / `state` / `code_verifier` accessors.
- **Breaking:** `vestibule_wisp/state_store` has been removed. Import `vestibule/state_store` from core `vestibule` instead — the API is identical.

### Dependencies

- Updated vestibule to 0.1.0

### Security

- State comparison in `callback_phase` now uses `state.validate` (constant-time) instead of `==`, closing a timing side-channel on CSRF token validation.
- The default OAuth session cookie is now host-bound (`__Host-vestibule_session`) instead of `vestibule_session`, preventing a sibling subdomain from tossing/fixating the session via a `Domain=.example.com` cookie. Added `is_host_bound_cookie_name` to validate custom cookie names.
